## 背景与动机

当前外部智能体接入方案不具备生产可用性：请求链路为「主管智能体 → 外部智能体调度器 → 第三方 HTTP 智能体」，多出一轮 LLM 推理，且在第三方完整响应返回前一直阻塞，导致延迟高、工具调用体验差、长耗时外部智能体频繁超时。

新的交互方向是保留现有普通聊天界面和主智能体框架：外部智能体作为 Supervisor 可调用的轻量工具存在。用户正常提问时，由主智能体自动判断是否需要调用外部智能体；用户 `@某个外部智能体` 时，作为强提示引导主智能体优先调用该外部智能体，但最终仍由主智能体负责组织问题、处理异常和整合回答。

## 变更内容

- 引入外部智能体网关，供 Supervisor 工具直接调用已注册的第三方智能体。
- 生产环境用轻量网关 + 平台适配器模型，替代当前「外部智能体调度子智能体」运行时路径，避免额外创建 ReActAgent 调度器。
- 支持主智能体根据场景自动调用外部智能体。
- 支持用户在普通聊天中 `@某个外部智能体`，作为主智能体优先调用该外部智能体的强提示。
- 将 Knot AG-UI 风格 SSE、BkAiDev SSE 等平台差异收敛到统一适配器契约下；腾讯内部
  平台实现落在 `ext/tencent/ai`，`core/ai` 仅保留通用第三方调用骨架。
- 保留现有外部智能体配置管理能力，并补充校验、密钥处理方向、超时与可观测性要求。
- 普通聊天记录仍以现有 `T_AI_MESSAGE` 持久化链路为准，外部智能体结果由主智能体整合进最终回复。

## 能力范围

### 新增能力

- `external-agent-streaming-gateway`：通过 Supervisor 轻量工具调用已注册第三方智能体，并将结果纳入主智能体回答。
- 主智能体自动决策：未 `@` 时也可根据问题场景和外部智能体描述选择调用。
- `@` 强提示：用户 `@某个外部智能体` 时，主智能体优先调用对应外部智能体。

### 变更的既有能力

- 移除面向前端的外部智能体直连流式 API 作为产品主路径；普通聊天仍走现有 AG-UI 对话接口。

## 影响范围

- 通用框架：`src/backend/ci/core/ai/biz-ai` 中新增平台无关的外部智能体网关、适配器契约、事件模型和结果收集能力。
- 腾讯内部平台实现：`src/backend/ci/ext/tencent/ai/biz-ai-tencent` 中新增或调整 AIDev、
  Knot 等平台适配器、协议解析、平台级配置校验和 HTTP 调用实现。
- Supervisor：注册用户已启用外部智能体为轻量工具，支持自动决策和 `@` 强提示调用。
- 复用配置表 `T_AI_EXTERNAL_AGENT_CONFIG`；密钥引用、协议选项、超时等字段可后续迁移补充。
- 前端继续使用普通聊天接口；若需要突出来源，可基于工具事件或最终回复元数据展示外部智能体来源。
- 需补充外部平台延迟、首 token 延迟、超时率、平台错误映射等指标与日志。
