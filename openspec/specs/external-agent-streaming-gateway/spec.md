# external-agent-streaming-gateway Specification

## Purpose

通过 Supervisor 轻量工具与平台无关的外部智能体网关，将已注册的第三方智能体（AIDev、Knot 等）纳入主智能体对话链路，替代额外 ReActAgent 调度路径，并统一流式协议、校验、超时与可观测性。

## Requirements

### Requirement: 外部智能体直连流式调用

系统必须提供用户选定外部智能体配置的直连流式调用路径，绕过 Supervisor 及任何外部智能体调度用 ReActAgent。

#### Scenario: 用户对流式调用已选外部智能体

- **当** 已认证用户对其名下已启用的外部智能体配置发起流式对话
- **则** 系统必须通过外部智能体网关调用已配置的第三方智能体，且不得创建 `ExternalAgentSubAgentDefinition` 作为中间 ReActAgent
- **并且** 客户端必须在第三方响应完成前收到增量 SSE 事件

#### Scenario: 用户调用已禁用或无权限的外部智能体

- **当** 用户对已禁用配置或他人所属配置发起流式对话
- **则** 系统必须在调用第三方平台前拒绝请求
- **并且** 响应必须包含对用户友好的错误信息

### Requirement: Supervisor 路由式外部智能体调用

系统必须支持通过轻量工具由 Supervisor 可选路由调用外部智能体，且该工具必须直连外部智能体网关。

#### Scenario: Supervisor 委派外部智能体

- **当** Supervisor 选择将任务委派给某外部智能体
- **则** 路由工具必须直连外部智能体网关
- **并且** 路由工具不得创建外部智能体调度用 ReActAgent

#### Scenario: 路由调用过程可展示进度

- **当** 路由调用过程中第三方平台产生流式输出
- **则** 系统必须通过现有 BK-CI AG-UI 事件管道向客户端推送进度事件
- **并且** 路由工具必须向 Supervisor 返回最终结构化结果

### Requirement: 平台适配器流式契约

系统必须通过带流式契约的平台适配器隔离各第三方协议差异。

#### Scenario: 通用框架与腾讯内部平台实现分层

- **当** 系统实现外部智能体流式网关与平台适配器
- **则** `core/ai` 必须只包含平台无关的请求模型、事件模型、网关、适配器契约和 AG-UI 映射
- **并且** AIDev、Knot 等腾讯内部平台的协议解析、鉴权 header 校验与 HTTP 调用必须位于 `ext/tencent/ai`

#### Scenario: 网关选择已支持的平台适配器

- **当** 外部智能体配置的平台字段为已支持值
- **则** 外部智能体网关必须选择对应平台适配器
- **并且** 适配器必须返回规范化外部智能体事件，而非聚合后的完整响应字符串

#### Scenario: AIDev 适配器处理标准 AG-UI SSE

- **当** AIDev 应用态或用户态接口以 `execute_kwargs.stream=true` 返回 AG-UI SSE
- **则** AIDev 适配器必须解析 `TEXT_MESSAGE_CONTENT.delta`、生命周期、推理、工具调用与错误事件
- **并且** 适配器必须支持 `thread_id` 作为多轮会话标识

#### Scenario: Knot 适配器处理 AG-UI 风格 SSE

- **当** Knot AG-UI 端点以 `input.stream=true` 返回 SSE
- **则** Knot 适配器必须解析 `TEXT_MESSAGE_CONTENT.rawEvent.content` 为文本增量
- **并且** 适配器必须从 `rawEvent.conversation_id` 提取外部会话标识

#### Scenario: 非流式平台接口不进入流式主路径

- **当** 平台接口文档明确不支持流式输出
- **则** 外部智能体网关不得将该接口作为流式主路径
- **并且** 系统必须将其标记为非流式兼容能力或拒绝流式配置

#### Scenario: 网关遇到不支持的平台

- **当** 外部智能体配置无匹配的平台适配器
- **则** 外部智能体网关必须在发起任何第三方 HTTP 请求前失败
- **并且** 服务端日志必须记录不支持的平台类型，且不得泄露密钥

### Requirement: AG-UI 兼容事件映射

系统必须将规范化外部智能体事件转换为 BK-CI 兼容的 AG-UI 事件。

#### Scenario: 第三方平台流式输出文本增量

- **当** 平台适配器产生文本增量事件
- **则** 直连模式必须将其转换为主对话文本流事件供客户端展示
- **并且** 路由模式必须将其作为外部智能体进度事件展示，直至 Supervisor 产出最终回复

#### Scenario: 第三方平台上报错误

- **当** 平台适配器产生错误事件或平台流失败
- **则** 系统必须转换为用户可理解的 AG-UI 错误或结束序列
- **并且** 系统必须在日志或指标中记录结构化诊断信息

### Requirement: 超时与取消控制

系统必须对外部智能体流式调用实施独立的超时与取消控制。

#### Scenario: 第三方平台长时间无首包

- **当** 第三方平台在配置的首 token 超时内未产生首个流式事件
- **则** 系统必须终止网关调用
- **并且** 客户端必须收到超时错误事件

#### Scenario: 流式过程中客户端断开

- **当** 外部平台流仍活跃时客户端断开或 BK-CI 运行被停止
- **则** 系统必须在支持的情况下取消上游第三方 HTTP 流
- **并且** 系统必须释放单次请求相关资源

### Requirement: 配置兼容与校验

系统必须在满足新网关运行时要求的前提下，保留现有外部智能体配置管理能力。

#### Scenario: 使用既有外部智能体配置

- **当** 既有已启用配置包含 platform、API URL、headers、agent 元数据
- **则** 网关必须根据既有 platform 字段选择运行时适配器
- **并且** 迁移期间必须容忍缺少显式协议元数据

#### Scenario: 新建或更新外部智能体配置

- **当** 用户创建或更新外部智能体配置
- **则** 系统必须按平台适配器要求校验平台支持与必填 URL/头字段
- **并且** 对无效配置必须返回用户可理解的校验错误

### Requirement: 外部智能体调用可观测性

系统必须对外部智能体网关调用提供结构化可观测能力。

#### Scenario: 外部智能体调用成功结束

- **当** 外部智能体调用成功完成
- **则** 系统必须记录平台、配置标识、总耗时、首 token 耗时、响应大小等指标
- **并且** 日志必须包含便于排障的关联标识

#### Scenario: 外部智能体调用失败

- **当** 外部智能体调用因超时、平台错误、解析错误或取消而失败
- **则** 系统必须记录失败类别与平台
- **并且** 日志不得包含密钥类 header 值或完整敏感请求体
